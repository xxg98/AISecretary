# 凯磊 AI 秘书项目介绍

## 项目定位

凯磊 AI 秘书是一套面向个人与组织协作的智能秘书系统。项目的核心目标是让每个人都拥有一个可沟通、可协作、可执行的 AI 秘书，通过“人和 AI 秘书沟通”以及“AI 秘书和 AI 秘书之间沟通”，帮助用户减少重复沟通成本，提升任务流转效率和工作协同效率。

在传统协作场景中，人们需要反复确认对象、内容、进度和结果。凯磊 AI 秘书希望将这些繁琐环节交给 AI 秘书处理：用户只需要用自然语言表达需求，自己的 AI 秘书负责理解、整理、分发和跟进；对方的 AI 秘书负责接收、提醒、归档和推动完成。

## 核心理念

项目围绕以下几个理念设计：

1. **每个人都有自己的 AI 秘书**  
   用户不再直接面对复杂系统，而是通过自己的 AI 秘书表达需求、安排事项、发送资料和跟进任务。

2. **AI 秘书之间可以协同沟通**  
   当任务涉及其他人时，用户的 AI 秘书可以将任务、文件、消息或待办传递给对方的 AI 秘书，由对方秘书完成提醒和管理。

3. **自然语言驱动工作流**  
   用户可以像和真人秘书沟通一样提出需求，例如“帮我把这个文件发给张三”“提醒李四明天上午确认合同”“让王五的秘书跟进一下会议纪要”。

4. **任务可追踪、结果可沉淀**  
   所有沟通过程、任务状态、文件流转和待办事项都可以沉淀为结构化记录，方便后续追踪、复盘和管理。

## 典型使用场景

### 发送文件

用户对自己的 AI 秘书说：

> 我需要给张三发个文件。

系统会完成以下流程：

1. 用户的 AI 秘书理解用户意图，识别接收人“张三”和待发送文件。
2. 用户的 AI 秘书将文件和相关说明发送给张三的 AI 秘书。
3. 张三的 AI 秘书接收该文件，并在张三的待办列表中创建一条待处理事项。
4. 张三可以在自己的待办中查看文件、处理事项并反馈结果。
5. 处理状态可以同步回发起人的 AI 秘书，形成闭环。

### 任务分发

用户可以对自己的 AI 秘书说：

> 帮我让张三今天下班前确认这份报价单。

AI 秘书会自动整理任务信息，包括任务内容、负责人、截止时间和相关附件，并将其传递给张三的 AI 秘书。张三的 AI 秘书负责在合适的时间提醒张三处理。

### 跨人协同

当一个事项需要多人参与时，AI 秘书可以帮助用户完成任务拆解、人员分发、进度跟踪和结果汇总。例如会议安排、资料收集、审批流转、项目跟进等。

## 核心能力

- **自然语言理解**：识别用户的指令、对象、时间、文件和任务目标。
- **智能任务创建**：将自然语言需求转化为结构化待办事项。
- **秘书间消息流转**：支持不同用户的 AI 秘书之间进行消息、文件和任务传递。
- **待办管理**：为接收方生成待办，支持提醒、处理、反馈和状态更新。
- **文件流转**：围绕任务和沟通场景完成文件发送、接收和归档。
- **状态追踪**：跟踪任务从发起、接收、处理到完成的全过程。
- **多端协同**：支持 PC 端、移动端以及后端服务协同工作。

## 产品价值

凯磊 AI 秘书希望解决工作协作中的以下问题：

- 降低人与人之间反复沟通和确认的成本。
- 减少任务遗漏、文件遗忘和进度不透明的问题。
- 将非结构化沟通转化为可执行、可追踪的任务。
- 让 AI 秘书成为个人工作入口和组织协作中枢。
- 提升个人办公效率和团队协同效率。

## 工程结构

当前项目主要包含以下模块：

```text
KaiLeiAISecretary/
├── backend-service/
│   ├── java-service/      # Java 核心业务后端
│   └── python-service/    # Python AI/语音/文档处理能力服务
├── collectors/            # MCP Server、主动式采集器、第三方系统数据采集工具
├── docs/                  # 项目级文档：架构、接口、部署、集成、产品
├── infrastructure/        # 本地开发和部署基础设施配置
├── scripts/               # 开发、构建、部署、数据库维护脚本
├── frontend-app/          # 移动端/多端前端项目
└── frontend-pc/           # PC 端前端项目
```

### backend-service

后端服务目录，包含 Java 服务和 Python 服务。Java 服务承担业务接口、用户体系、任务流转、文件管理、秘书间协同等核心业务能力；Python 服务承载语音、文档解析、OCR、Python AI 工具链和长耗时任务等能力。

### collectors

采集器目录，用于放置 MCP Server、主动式采集器和第三方系统适配器。例如当 AI 秘书需要查询财务数据时，可以通过财务采集器调用用友、金蝶、SAP 或自研财务系统，并将结果结构化返回给秘书。

### docs

项目级文档目录，用于沉淀架构设计、接口协议、部署说明、集成方案和产品需求。

### infrastructure

基础设施目录，用于存放 Docker Compose、本地中间件、Nacos、MySQL、Redis、RabbitMQ、MinIO、Nginx 等配置模板。

### scripts

脚本目录，用于放置本地开发、服务启动、构建打包、数据库维护等脚本。

### frontend-pc

PC 端前端项目，用于提供桌面办公场景下的 AI 秘书沟通、任务管理、文件查看和协同工作界面。

### frontend-app

移动端/多端项目，用于支持移动端或小程序等场景，让用户可以随时和自己的 AI 秘书沟通，并处理待办事项。

## 本地开发快捷命令

启动本地基础设施：

```bash
./scripts/dev/start-infra.sh
```

停止本地基础设施：

```bash
./scripts/dev/stop-infra.sh
```

启动 Java 服务：

```bash
./scripts/dev/start-java.sh
```

启动 Python 服务：

```bash
./scripts/dev/start-python.sh
```

执行基础校验：

```bash
./scripts/dev/check-all.sh
```

## 示例流程

以下是“给张三发文件”的简化业务流程：

```text
用户
  ↓ 自然语言指令
用户的 AI 秘书
  ↓ 解析意图、识别文件和接收人
秘书间通信服务
  ↓ 分发文件和任务
张三的 AI 秘书
  ↓ 创建待办并提醒
张三
  ↓ 处理文件和任务
状态反馈
  ↓
用户的 AI 秘书
```

## 未来方向

项目后续可以继续扩展以下能力：

- 更强的 AI 意图识别和上下文理解能力。
- 更完善的组织通讯录和人员关系识别。
- 更智能的任务优先级、提醒策略和自动跟进机制。
- 支持审批、会议、日程、合同、客户跟进等更多办公场景。
- 支持企业级权限、审计、数据安全和知识库集成。
- 打通更多第三方办公工具、财务系统、ERP、CRM、OA 和消息平台。

## 总结

凯磊 AI 秘书不是一个简单的聊天工具，而是一个以 AI 秘书为入口的智能协作系统。它通过自然语言交互、秘书间协同、待办管理和文件流转，把工作中的沟通请求转化为可执行、可追踪、可闭环的协作流程，从而帮助个人和团队显著提升工作效率。
